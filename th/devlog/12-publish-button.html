EP.12

ปุ่มเผยแพร่สำหรับเอเจนต์ โดยไม่ให้กุญแจ

17 พ.ย. 2026·
  • สตูดิโอ
  • เผยแพร่
  • ความปลอดภัย

จนถึงตอนนี้ คำว่า "เสร็จ" ในสตูดิโอแปลว่าไฟล์นอนอยู่ในโฟลเดอร์ การเอาขึ้นเว็บจริงยังเป็นผมที่ต้องคัดลอกและ push เองทุกครั้ง ผมเลยขอครึ่งที่ขาดไป คือดูผลงานจริง เช็กว่าไม่มีของส่วนตัวหลุดไปด้วย เผยแพร่ และแจ้งผมทาง Discord

สองส่วนแรกง่ายสุด การ์ดอนุมัติแสดงหน้าจริงในกรอบแล้ว (กั้นไว้ ให้หน้านั้นเอื้อมถึงสตูดิโอไม่ได้) และมีตัวสแกนทำงานก่อนถึงตาผมอนุมัติ มันบล็อกของลับ ไฟล์ส่วนตัว ที่อยู่เซิร์ฟเวอร์ อีเมลที่ไม่ใช่ของผม ลิงก์เสีย และฟอร์มที่แกล้งทำเป็นส่งข้อมูล งานโค้ดจะรันเทสต์ด้วย ส่วนโดเมนแปลกๆ กับ TODO ที่ลืมไว้ แค่เตือนไม่บล็อก

ส่วนยากคือใครเป็นคน push สตูดิโอรันโค้ดที่ AI เขียน ถ้าเก็บกุญแจ GitHub ไว้ข้างใน มันก็ปลอดภัยแค่เท่าเอเจนต์ที่ไม่ระวังที่สุด ดังนั้นสตูดิโอไม่ถือกุญแจเลย การเผยแพร่ผ่านตัวช่วยเล็กๆ ที่เป็นของ root มี deploy key ของตัวเองที่ root อ่านได้คนเดียว และมีกฎ sudo ข้อเดียวที่อนุญาตเฉพาะคำสั่งนั้น ตัวช่วยตรวจซ้ำทุกข้อเอง การข้ามในหน้าเว็บจึงไม่มีผล มันไม่ยอมเขียนทับคอมมิตที่ทำไว้ที่อื่น และกับโค้ดของบอทมันไม่แตะสาขา main เลย แต่ส่งเป็นอีกสาขาให้ผมตรวจ

ตอนทดสอบเจอบั๊กสองตัว ในเครื่อง ไฟล์ที่ถูกแก้เป็นข้อความความยาวเท่าเดิมหายไปจากสาขาที่ push เฉยๆ เพราะระบบตรวจการเปลี่ยนแปลงแบบเร็วของ git คิดว่าไม่ได้แตะ ทางแก้คือบังคับให้เทียบเนื้อหาจริง ส่วนบนเซิร์ฟเวอร์ ตัวช่วยรันในสภาพแวดล้อมที่เคลียร์ไว้ และสภาพแวดล้อมนั้นไม่มีโฟลเดอร์ที่เก็บเครื่องมือลดสิทธิ์ โหมดสาขาจึงพังพร้อมข้อความ "git failed" ที่ไม่บอกอะไรเลย ตอนนี้เพิ่มโฟลเดอร์นั้นแล้ว

สิ่งที่พูดได้ตามจริง ทดสอบแบบไม่ push จริงบนเซิร์ฟเวอร์จริงผ่านทั้งสองโปรเจกต์ และรันทั้งสายด้วย AI ปลอม งานปกติถูกเผยแพร่ ส่วนงานที่มีอีเมลหลุดถูกบล็อก ผมยังไม่เห็นการเผยแพร่จริงหรือข้อความ Discord จากงานจริง นั่นคือสิ่งที่ต้องดูต่อไป

บทเรียน: ปุ่มที่เปลี่ยนโลกจริงควรเป็นปุ่มที่เชื่อหน้าเว็บน้อยที่สุด วางการตรวจไว้ในที่ที่หน้าเว็บข้ามไม่ได้
