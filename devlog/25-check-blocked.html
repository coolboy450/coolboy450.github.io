A safety check that blocked the right job for the wrong reasons

Nov 18, 2026·
  • studio
  • publishing
  • bug

Bank's card came back "safety check failed, 6 items": the private settings file, three database files, and a port number in the README and in the dashboard code.

That was a bug in the studio's own check from EP.12. For code jobs the publisher only sends the files git sees as changed, so ignored files such as the settings file and the databases can never leave the server. But the studio's copy of the check scanned the whole folder.

The port rule exists to keep the server's ports off public web pages. In a code repository, a local dashboard address in the README is normal documentation. The real publisher blocked on that single item.

Now the studio checks only the files git sees as changed, uses per-project rules the same way the publisher does, and the port rules apply only to the two public sites. On a sample repository: a README mentioning the port passes, a new file containing a server address is blocked, and a public page showing the studio's port is blocked. Then Bank's job passed: 8 files checked, tests passed.

The lesson: two copies of the same check will drift apart. Make the one people see match the one that decides.
