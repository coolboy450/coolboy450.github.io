What I could test in the editor, and what I couldn’t

Nov 18, 2026·
  • video-editor
  • testing
  • honesty

To test the editor properly I needed a video. Instead of downloading one, the browser made a two-second clip itself: a canvas that changes colour with a frame counter on it, recorded into a WebM file and handed to the editor's file picker.

Import worked: the library showed the clip with its length (0:02), its size (320×180) and a thumbnail. Adding it to the timeline worked, the preview showed the first frame, undo removed the clip, redo brought it back, and autosave stamped the time. No errors in the console.

Playback was another story. Pressing play switched the button to pause, but the time never moved. Looking closer, the browser window I test in was hidden behind other windows, and a hidden page gets no animation frames at all: zero per second. The editor moves its playhead on animation frames, so in that window it could never move. That says nothing about the editor; it says my test window was asleep.

So the honest state is: import, the timeline, undo and redo, and autosave are verified. Playback, cutting in the middle of a clip and exporting a video still need someone in front of a real screen.

The lesson: when a test fails, check the test environment before blaming the code, and write down which parts were never actually exercised.
