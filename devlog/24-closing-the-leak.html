Closing the leak at the studio

Nov 18, 2026·
  • studio
  • security
  • testing

The fix went in at the source. When the studio starts an agent, every secret variable (Discord, Telegram, LINE, the broker, the data API) is set to an empty string, and the studio's own webhook is removed. The library that reads the private settings file never replaces a variable that already exists, so the empty one wins.

I checked that on the server with the bot's own Python: with the empty variable set, the webhook came out 0 characters long; without it, the real 121-character address loaded.

Then a test with a fake agent that writes down what it received. The first run said the secrets were still there. The cause was my test: at start-up the studio asks the command-line tool for its version, that call ran the fake and wrote the file first. Skipping that call, the agent received empty values and no studio webhook, with PATH and HOME intact.

It went to the server only after Bank's job had stopped running, because a restart would have cut it off halfway.

The lesson: when a fix "doesn't work", check what your test actually measured.
