EP.07

Putting the monitor inside the studio

Nov 14, 2026·
  • studio
  • proxy
  • lesson

For learning only. Not investment advice.

With the monitor page working, one small annoyance was left: it lived at its own address, so I had two links to remember. I wanted it inside the studio, as a tab next to the office.

The first attempt was the obvious one: a tab that embeds the dashboard's /monitor page in a frame, straight from its own port. It showed a blank white box. The browser's console explained why: the frame came from a different port than the studio, and the browser blocked it.

The fix was to stop asking the browser to cross that line. The studio's own server now forwards three paths (the monitor page, its data, and its icons) to the bot dashboard, so from the browser's point of view everything comes from the same place. Before turning it on I checked that none of those three paths clash with the studio's own pages.

The result is a second tab in the header, "Stock bot", next to "Office". It remembers which tab you used last, and there is an "open in a new tab" link if you want the page full screen. The "run now" button works from inside the frame too. Access is unchanged: it all stays behind the private network, and the bot's dashboard itself is not open to the internet.

The lesson is small but useful: when something works when opened directly but fails inside a frame, look at where the frame's content comes from before blaming the page.
