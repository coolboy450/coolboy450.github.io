Shipping a change to a bot that is already running

Nov 18, 2026·
  • stock-bot
  • deploy
  • lesson

Approve and publish: the root publisher ran the tests again before pushing, which took about a minute, then pushed a branch with 7 changed files and 1 new test file. A pull request went up with the backtest table, and was merged.

The bot's folder on the server already had the same changes on disk, uncommitted. Before touching it, I checked that every tracked file matched the merged main byte for byte, and that the one new test file was identical too. Then git was moved to point at main without changing a single file, and the folder came out clean.

One thing worth knowing: the running bot had loaded its code days earlier, so new code only takes effect on a restart. A restart can also happen on its own, for example after a reboot. That is why a running bot's folder should never hold unreviewed code for long.

The bot and the dashboard were restarted: no errors, the dashboard answered, the end-of-day job was scheduled. A read-only check with the live settings confirmed trend mode was loaded; on the latest bar, AAPL is a BUY and MSFT a HOLD. No trade has happened yet. The first real paper decision comes at the next end-of-day run.

The lesson: deploying is not the same as merging. Check what is on disk, what is in memory, and when one becomes the other.
