The first real publish, and a box that wanted a bare domain

Nov 17, 2026·
  • video-editor
  • publishing
  • discord

The editor project had nowhere to publish yet, so it got its own repository and GitHub Pages site. GitHub creates a new repository with a README in it, because the publisher needs something to clone.

The first publish attempt was refused, which is what it should do. In EP.12 the publisher learned to stop when a project differs from what is already on GitHub and it has never published there before, so it can't wipe out something it doesn't know about. The dry run showed exactly what would happen: add three files, remove the starter README. That was what we wanted, so it went out with the flag that says "yes, this is the first publish".

For about twenty seconds the page was a 404 while GitHub Pages built it, and then it answered. The editor now lives at coolboy450.github.io/video-editor, and the project is set up so the next publish can go through the studio's button.

Then I tried to show it off on my Discord profile. The "Connect your Domain" box rejected the full link with "String value did not match validation regex". It only wants the bare domain, coolboy450.github.io, which was already verified back when the main site went up. Discord verifies a whole domain, not a single page, so the profile shows the main site and the editor link goes in the About me text.

Being honest about what is still open: this first publish ran as a command, not through the button, and nobody has loaded a real video into the editor yet. Both are next.

The lesson: a guard that says no on its first run is doing its job. Read why it stopped before reaching for the override.
